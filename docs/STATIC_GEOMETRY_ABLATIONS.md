# Static Semantic–Geometric Localization: Stage 1

**Question:** Given only instruction + static map, can named landmark geometry localize a goal without RGB, Depth, UAV pose, or future trajectory?

## Controlled ablations

| Variant | Model | Training | Question |
|---|---|---|---|
| S0 | Referenced Landmark Prior | fixed, no training | How strong is the landmark prior? |
| S1 | S0 + explicit east/near/between/along geometry | fixed, no training | Does geometry help? |
| S2 | S1 + typed Edge-GATv2 | trainable | Does graph message passing help? |
| S3 | S2 + verified observed RGB | future experiment, OFF | Does vision provide new evidence? |

Architecture: whole Building polygon = ONE node, whole Road polyline = ONE node, each reliably parsed language relation = ONE node. Vertices are coordinates, **not** nodes. Static graph differentiates building-building-near, building-building-overlap, building-road, road-road-connected (only intersecting or touching physical polylines, tolerance 1m) and relation-anchor edge types. Typed edge embeddings carry directional XY, physical distance and boundary distance. The previous graph.py k-NN + UAV-to-all architecture is NOT used by this static ablation.

Static goal field is the full **28x28 global grid**, not a candidate neighborhood. Names are bound deterministically to mapped polygons. Homonyms are left ambiguous (OR scores). No unknown road geometry is synthesized. East/west/north/south are defined in map-world axes, not UAV yaw.

**Metrics**: R@1/20m, R@4/20m, R@8/20m (top-k grid centers within 20 physical meters) and top1 NE in meters. The exact same records and denominators are used for each model. Validation on Val Seen selects checkpoints (R@8/20m); Val Unseen is an independent final report. Check sigma sensitivity (10/20/30/40m) before comparing with historic HETT referenced-mask prior. The new S0 is a newly implemented spatial prior; numerical parity with HETT is NOT assumed.

For static experiments, deduplicate by exact `(map_name, instruction)`, preserving
the first source record without consulting target coordinates. Remove training
queries overlapping validation by this same key. Report conflicting labels among
duplicate source queries rather than resolving them by proximity to GT.

## Data and real road requirements

Source: independent CityNav JSONL generated by scripts/prepare_citynav.py with instruction, named landmark contours, target_xy (LABEL ONLY), world_bounds, map_name, and physical_map_sizes. Road metadata is an optional map-keyed JSON object, e.g.:

```json
{"cambridge_block_3": [
 {"id":"osm-way-12","name":"Main Road",
  "polyline":[[123.4,567.8],[125.8,574.6]],
  "coordinate_system":"world"}
]}
```

**Road topology semantics:** if two source road entities carry OSM node identities (optional `osm_node_ids` list), they are `roads_connected` only when those IDs intersect. When IDs are absent, a shared physical endpoint within 1m may infer connectivity. Geometries that merely cross in 2-D are tagged `roads_crossing`, **not** navigably connected (e.g., overpass).

For GeoJSON linework already transformed into the CityNav world frame:

```bash
python scripts/prepare_roads.py \
  --geojson data/roads_projected_aligned.geojson \
  --bounds data/citynav_bounds.json \
  --output data/roads.json \
  --aligned-citynav-world-xy
```

The script does not georegister GPS/OSM lat-lon: that map alignment must be supplied and verified separately. If GeoJSON `properties.osm_node_ids` is provided for a way, it is carried to per-segment road entities.

Road polylines MUST already be registered in the same CityNav world XY meters, or explicitly tagged coordinate_system=normalized after projection via the same map bounds. **Do not pass GPS lat/lon as world XY**. If authentic road data is absent, remove --roads-json, run building-only ablations and report road relation coverage as unavailable; never fake a road connection.

Use `prepare_citynav.py --static-only` for S0–S2: it emits one static record per
source annotation, binds only objects explicitly typed `Building`, and excludes
pose, RGB and teacher future fields. CityRefer `TrafficRoad`/`Footpath` contours
are surface polygons; they cannot be silently relabeled as buildings or used as
road centerlines. Run `python -m scripts.prepare_static_splits --data-dir data
--output runs/static_graph_bs16/query_deduplication.json` after converting all three
splits, then `scripts.audit_static_data` to verify separation and contour identity.

## RTX Pro 6000 96GB, batch size 16

Single GPU, BF16 for GAT; pretrained BERT frozen. S0/S1 are evaluated without training. Start with 5 epochs, bs16, no full navigation, no SigLIP2. Steps:

```bash
git checkout 2027-CVPR/semantic-geometry-localization
pip install -e '.[dev,foundation]'

python -m graphnav.static_experiment \
  --train data/graphnav_train_seen.jsonl \
  --val-seen data/graphnav_val_seen.jsonl \
  --val-unseen data/graphnav_val_unseen.jsonl \
  --roads-json data/roads.json \
  --device cuda --batch-size 16 --epochs 5 \
  --output runs/static_graph_bs16
```

Omit --roads-json when real roads are unavailable. Results: best.pt, static_localization_metrics.csv and .json under the output directory. No online CityNav SR/SPL claim is made.

For the verified RTX 6000 environment, install with
`pip install -c configs/static_geometry_rtx6000_constraints.txt -e '.[dev,foundation]'`.
The building-only run uses `--max-roads 0` to avoid unused graph padding.
`training_history.csv` and `history.json` persist every epoch's sample-weighted
loss, train/validation time, exact throughput, peak allocated/reserved GPU memory,
and Val Seen metrics. `last.pt` includes optimizer state; `best.pt` is selected
only on Val Seen. `frozen_text_features.pt` preserves the exact frozen BERT
features used for final evaluation. Reuse it with `python -m
scripts.diagnose_static_run --data-dir data --output runs/static_graph_bs16` for
per-query CSVs, sigma sensitivity, paired bootstrap intervals and self-edge-only
topology intervention. BERT remains frozen and its cache stores CLS vectors
without retaining full token-state buffers.

## Later, not part of static phase

graphnav/visibility_graph.py stores only **visible AND confidently identity-matched** landmark evidence, optionally tagged with observed Depth, with an explicit historical confidence. It must not be fed into S0–S2. S3 can combine this evidence with previously observed RGB and frozen SigLIP2. Only after goal localization improves should trajectory planning and separately calibrated Stop be trained, followed by genuine closed-loop SR/SPL.
