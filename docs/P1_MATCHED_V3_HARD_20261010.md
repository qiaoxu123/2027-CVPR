A3均为h128/4heads、完整BERT96 Token、28×28候选、relative_position=False；batch16、BF16、workers4、seed0、5Epoch和数据划分一致，仅初始化不同。Scratch训练265.99s，P1初始化微调269.32s，额外P1预训练67.42s；不含缓存、准备及验证。逐轮耗时/峰值显存与来源SHA在`reports/p1_v3_hard_matched_20261010`，并保留全部Last/Best本地权重及源码快照。

困难负样本由同地图、同类别、相似距离/轮廓面积的真实具名地标构成，要求在所请求方向的相反侧且与正样本相距>40m。共9262个方向样本含25260个负标签，正反及派生样本沿用v2 family-disjoint划分。仅Loss访问标签，模型推理白名单不变。权重0.1的margin Loss第一轮平均0.03436，后续为0；该条件保证负例合法，但它们对已学会方向的网络可能很快变得容易。不能把零负例Loss视作真实CityNav性能提升，也不能把同方向多解地标强制当作错误负样本。

P1内部dev方向符号准确率100%仍伴随约23.07m的正反位移一致性误差。微调后的237条受控方向测试：Scratch原始/交换方向准确率61.18/71.73%、预测翻转35.44%；P1v3为55.27/70.46%、翻转33.33%。交换后的镜像点是人工诊断标签，非真实导航GT。747条合法坐标平移的对齐logit误差0.27753→0.21198，仍非零；仅世界原点变化误差约3–4e-5。这些诊断不能证明完全消除了绝对位置依赖。

最可能的机制是几何关系预训练与实际外观丰富、多解的目标描述存在任务差异，但本实验没有单独证明因果。严格合法的反向关系和较低Loss不足以保证迁移。保留Scratch；不增加第四个P1主要方案。后续以相同监督训练各自Trajectory/Stop并做完整Seen及一次冻结Unseen对照，结果在最终系统报告中追加，不能用静态Recall替代闭环SR。
