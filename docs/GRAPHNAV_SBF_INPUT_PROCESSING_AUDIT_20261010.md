# GraphNav 与本地 SBFNav 输入/处理差异核验

本报告基于实际使用的冻结本地复现源码，不代表作者官方实现。最终GraphNav Unseen仍未评估；以下结构差异及负对照不等于宣称某项新设计有性能增益。

SBF源码根：`../SBFNav-CityNav-Reproduction/runs/sbfnav_main_e20_bs16_s0_20260929/source/`。全部Python SHA已记录在统一评估各次`metrics.json`。本地最佳合法已存Checkpoint/SHA/原配置见统一协议报告。

| 输入/处理 | 本地 SBFNav | 当前 GraphNav | 证据与限制 |
|---|---|---|---|
| 基础语义地图 | 全局具名地标栅格、引用mask；同名保留最大Polygon | 完整具名引用轮廓片段，最多16；观察到的其他具名区域作为视觉辅助节点 | 相同RAW源/名称，原生预处理差异明确保留，不能偷偷改变基线 |
| 语言 | 同一冻结SigLIP模型的Token/池化文本，按其官方文本长度 | 完整冻结BERT96 Token；Unseen指令没有96长度截断 | 保留Token不等于已具备图文对齐；两者Tokenizer/预训练空间不同 |
| 全局视觉定位 | 9通道状态包含已观测RGB/高度、FOV、已探索区域和轨迹；CNN空间特征逐位置与语言Token Cross-Attention | A3首先只用语言+地图构成784候选；P3增加实际地标ROI向量与几何/置信度残差 | RGB已接入P3，但原A3的语言特征由几何任务训练，目标颜色/外观的使用未证实 |
| 视觉重排序 | 真实已观测累计RGB的候选区域crop，经SigLIP与指令/地标文字、候选相对几何交互 | SigLIP2 Large/384 Patch Tokens训练跨帧地标匹配；在线按公共位姿+轮廓关联节点，再修正全784目标分布 | Graph没有局限于Top20 ROI，但当前视觉监督主要是地标身份/类别，而非目标描述—候选外观 |
| 几何 | 候选相对于agent/地标中心的显式位移、距离、方位 | 逐784候选对完整轮廓的相对/有符号边界几何，真实道路区域 | Graph路径更强的轮廓几何；没有证实真实道路中心线/拓扑，不能虚构 |
| 历史 | 已观测RGB/区域/轨迹作为空间状态 | 可信地标向量均值/最大置信度、位姿和观察区状态；当前位置版也单独测试 | 位姿/覆盖记录存在，但当前轨迹Head不直接消费更新后GAT latent；不是完整时序Pose Attention |
| 轨迹/Stop | 本地原模型有高度/进度预测、有界重规划；所选Checkpoint不输出policy Stop | 多模态学习路径/模式、25%收敛残差、学习Stop+预测目标到达+公开合法高度门控 | SBF的False-Stop为null，不能当作0错误；Graph Stop仍有高错误比例 |

## 为什么“地标检索好”未自动变成“导航好”

准确公开位姿与公共Polygon能够按几何投影关联地标。当前在线系统不需要通过检索去猜一个ROI对应哪个已知区域；源名称和完整轮廓完成关联。因此跨帧同地标R@1/R@5测的是编码器实例一致性，不能代替指令中“灰屋顶/白车/第三栋”等目标外观与候选区域的匹配。

同权重、同当前ROI/几何/置信度Seen128：实际向量、清零向量、当前帧内同类别交换，SR都40.625%；SPL39.0822/39.1238/39.1488%，实际向量没有胜过控制。零向量控制仍保留实际RGB源覆盖/Depth质量、已观察子集和区域几何；不是删除全部传感器信息。同类别交换的单例不变。它们是小样本机制诊断，不能据此断言所有RGB信息在全量数据上毫无价值。

当前地标ROI训练源自人类前缀；视觉几何、已观察区域和专家位置存在合法的训练分布相关性。真实运行偏离专家时可能不适用。这是需要受控验证的分布偏移假设，不是已发现未来信息泄漏。恢复Trajectory/Stop训练不会自动解决P3视觉融合的这项偏移。

## 下一项最值得验证的假设

保持强A3并冻结视觉Backbone，训练直接由完整指令Token条件化的实际已观测Patch/区域外观匹配，让颜色/屋顶/车辆等描述能够作用于全局候选；未观察区域仍未知。只用实际可见的弱区域/点监督和同地图相似外观负样本，不把Polygon投影当完美分割，不把GT目标/ID放入forward。使用真实Train闭环观测覆盖错误候选附近，而不仅使用专家靠近目标的前缀。通过实际向量/零向量/交换对照证明新增信息，再测Stop附近目标确认。

应先检验监督和融合是否正确，再考虑LoRA或增大模型。当前Large与Base检索的净差只有1/115身份，且原生384/224分辨率也不同；无法仅凭此支持“更大视觉模型就能提高导航”。
