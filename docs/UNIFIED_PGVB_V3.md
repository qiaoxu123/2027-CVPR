# UnifiedPGVB-V3: Decoupled Geometry and RGB-D Global Belief

Status: **code committed for LOCAL testing; no GPU fitting or measured gains.**

## Exact V3 architecture

- **Geometry (coarse, global 28x28):** original entire BERT
  instruction tokens and public named landmark Polygons through the V2
  token/landmark attention and relative-Polygon geometry. V3 zeros the
  legacy parsed rule/relation tensor inputs. Training GT target Polygon
  supervises global region mass **after forward**.
- **Visual (fine, global 384x384):** one frozen
  google/siglip2-large-patch16-384 provides both actual-frame
  image-patch features and whole-instruction text features. A small
  depth adapter and BERT-token cross-attention augment visual features.
  They are NOT second ViT/CLIP backbones.
- **Fixed yaw, public-landmark sampling:** up to five top-down local RGB-D
  frames around the first public named reference Polygon; same world
  yaw for every frame, at a controlled altitude. Only public reference
  geometry and world bounds select view locations. No target GT
  is used in selection. No named anchor => NO visual evidence.
- **Same world grid:** both global heatmaps share public
  xmin/ymin/xmax/ymax; each frame is registered using actual Footprint
  TL/TR/BR/BL corners. Unknown/unobserved locations are explicitly
  masked, with **zero visual correction**.
- **Fusion:** 28x28 geometry logits upsample to 384x384, plus bounded
  registered visual evidence * observed mask. Final product is ONE global
  384x384 Belief. 384x384 is a goal-distribution grid, not a camera image.
- **GT supervision (TRAIN-only private):** coarse Goal CE and Polygon
  region-mass loss; fine fused Goal CE and Polygon region-mass loss;
  text-versus-observed-patch contrast; optionally GT target RGB-crop
  Teacher-versus-observed-patch contrast using the SAME frozen SigLIP2.
  The GT image and GT Polygon are **never forward inputs**.
- **Evaluation:** offline Geometry-only vs Fused global R@1, R@5,
  R@20 at 20m, mean Top1 NE, fixes/breaks and visual support.
  No navigation SR/OSR, trajectory, Stop or controller changes.

The geometry branch reuses V2's pretrained Geometry weights and
learns its own loss. The visual branch learns a depth adapter, text
conditioning and small patch projection, with the SigLIP2 ViT frozen.

## Data and interpretation limitations

**Depth:** CityNav supplies a 2.5D vertical depth proxy
(camera world z minus raster surface height), NOT real stereo RGB-D
depth and NOT a perspective/occlusion-aware 3D rendering.

**Polygon:** official CityRefer contours may not be accurate pixel
instance outlines (especially cars). Thus the training objective is
probability mass inside a weak region, not pixel-level Dice/BCE ground
truth. Positive native patches are generated by conservative geometric
overlap with Polygon, restricted to valid observations; that is a
weak visibility proxy, not proof of visible instance identity.

**Image size:** the input RGB is one native local 384x384 observation
per viewpoint, the ViT encodes 24x24 patches; the output 384x384
global target Belief is NOT the same coordinate system as camera RGB.
Full-map RGB must never enter student inference. Target crop from the
source orthomosaic can ONLY appear in private TRAIN teacher loss.

**Yaw:** zero yaw means engineering-world axis orientation, not
verified geographic North. Register every frame via its Footprint even
if all frames use identical yaw.

**Text:** full original instruction goes through BERT tokens for
both branches. Frozen BERT has the existing V2 token limit; SigLIP2
text embeddings may also truncate long text, so audit long instructions
before interpreting fine-grained attribute learning.

**Spatial resolution:** the 28-to-384 geometry upsample is smooth,
not newly observed fine-scale information. The visual branch can
refine only where legitimate local RGB-D observations provide evidence.
A 384x384 target map for an extensive city can still be meters-per-cell.

## Local operation

Check out the experiment branch (NOT main):

    git fetch origin
    git switch experiment/unified-pgvb-v3-decoupled-rgbd-20261106

Dependencies: the existing GraphNav environment with Torch,
transformers, OpenCV, rasterio, numpy, shapely, and frozen
SigLIP2-Large / BERT weights.

CPU-only regression checks:

    python -m pytest -q tests/test_unified_pgvb_v3.py

Prepare a small, original Revised TRAIN-only cache. Fill paths
with real local files. ground-levels JSON is a map-name -> world
ground-Z map (PUBLIC metadata), not target GT:

    python scripts/unified_pgvb_v3_pilot.py cache \
      --source-v2 /path/to/verified_unified_pgvb_v2.pt \
      --train-jsonl /path/to/revised_train.jsonl \
      --objects /path/to/cityrefer/objects.json \
      --ground-levels /path/to/public_ground_levels.json \
      --rgbd-dir /path/to/citynav/rgbd \
      --cache runs/v3_pilot_cache_s42 \
      --limit 128 --views 5 --fixed-yaw 0 \
      --altitude-m 80 --offset-m 35 --device cuda

Fit V3 (original Geometry weights initialized from verified V2;
SigLIP2/BERT frozen), evaluate physical-object-heldout TRAIN dev:

    python scripts/unified_pgvb_v3_pilot.py train \
      --source-v2 /path/to/verified_unified_pgvb_v2.pt \
      --cache runs/v3_pilot_cache_s42 \
      --output runs/v3_pilot_s42 \
      --epochs 2 --batch-size 1 --seed 42 --device cuda

After the 128-row smoke, use a **NEW cache directory** and e.g.
1000 TRAIN queries if local resources allow. Cache immutability
is enforced for source hashes/protocol; output checkpoints never
silently overwrite existing experiments.

Outputs:

- cache/manifest.json: data SHA, fixed yaw/height and provenance
- cache/public/*.pt: student input tensors only; NO target ID/Polygon/crop
- cache/private/*.pt: target XY, Polygon, target RGB Teacher and target ID
- output/last.pt: new-format V3 weights; original V2 untouched
- output/report.json: offline Geometry and Fused paired results

The native dense SigLIP2 cache is large: approximately 5.6 MiB
for FIVE half-precision 576x1024 observation-token tensors per query,
before metadata and GT teacher, so do not start full TRAIN caching
without checking available SSD space.

## Mandatory local review

1. Run V3 CPU unit tests before fitting; audit sample tensor dimensions
   and map registration, including 90-degree footprint changes.
2. Change target_xy while holding PUBLIC references fixed: planned
   observation positions and yaw must be identical.
3. Inspect the sample cache and student forward API: target GT and
   object IDs may be accessed only in TRAIN loss or scoring, not
   viewpoint selection, feature encoding or forward.
4. Report number of samples with public anchors, actual valid RGB-D
   pixels, private valid Polygons, and target-overlap visual patches.
   If few patches overlap, do not claim successful visual recognition.
5. Compare Geometry vs V3 Fused on the same TRAIN-heldout physical
   targets, including cases with no RGB support. R@K measures whether
   one of top-K world goal cells is within 20m of TRAIN GT; this is
   NOT closed-loop success.
6. If no improvement, investigate Polygon accuracy, actual target
   visibility, SigLIP text truncation and geometric co-registration
   before tuning large ViT or changing network depth.

This first pilot intentionally includes **no navigation controller,
no collision-aware flight-planning, no learned viewpoint selection, no
3D point cloud and no additional visual backbone**.
