# A2 当前失败机制：代码核对

仅阅读正在运行的V4所复用的训练及推理代码，不改变代码、数据或实验规则。本检查补充前六轮数字，不能替代图片核对或完整导航评估。

## 已确认的两个限制

1. 正例表示“有助于定位目标”，不表示“确实是指令所说的物体”。`relation_v3_data.build_training_row` 中，候选需要满足有效、类别兼容及其位置距训练目标20米内等条件，才获得定位正例；物体身份标注掩码全部为假。`relation_v3_fusion.spatial_utility_labels` 也明确采用距离条件。这是一种可用的位置监督，但附近的同类错误物体也可能满足条件。因此，现有定位正确率不能单独检验文字与物体对应是否正确。

2. 方向和距离的预测没有直接移动最终候选位置。`relation_v3_loss.relation_v3_loss` 训练方向和距离输出；但 `relation_v3_runtime.evidence_forward` 与 `relation_v3_fusion.proposal_with_quality` 构造位置分布时，直接使用候选已有世界坐标、候选评分与可信程度，没有读取预测的方向或距离输出。方向和距离任务可能通过共享网络帮助评分，不能说它们完全无用；但若正确候选本身的位置投影错误，不能期待这两个输出直接把位置修正回来。

## 对后续改进的影响

目前无法认定“仅语义关联出错”。应先在训练和内部检查数据中分别确认：

- 真实目标是否出现在检测候选中；仅靠20米距离不能证明物体身份。
- 有正确候选时，新模块有没有选择它，近邻同类物体是否被混淆。
- 正确物体的世界位置是否准确；候选投影偏差与候选选择错误要分开记录。
- 原模型已经正确时，新模块为何仍给出相反位置；检查哪些公开可见的证据足以支持修改。

有图片或身份核对证据后，才决定下一版更适合增加可靠的文字—物体对应训练，还是修改位置计算。不能直接把附近物体当成身份正例，也不能仅因为网络输出方向和距离，就宣称最终推理已用它们修正位置。

当前25轮实验继续保持原样。未使用独立校准或正式Seen/Unseen数据，未提出在测试集上选择改法，未证明A2超过A0。
