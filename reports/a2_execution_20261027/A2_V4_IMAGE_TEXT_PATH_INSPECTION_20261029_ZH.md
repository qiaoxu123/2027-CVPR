# 当前文字与图片如何共同评分：实现核对

目的：确认候选评分是否直接使用冻结模型既有的图文相似度。只阅读代码，不修改当前训练、评估、输入或权重。

- [x] `perception.FrozenBoxCropEncoder.images` 使用原冻结SigLIP2的 `get_image_features`，归一化后保存真实候选裁剪特征。
- [x] `core.InstructionLandmarkEncoder` 接收冻结BERT的指令和地标名称特征，经新增可训练投影及注意力形成地标上下文。
- [x] `core.BoxLandmarkRelationScorer` 将图片特征经可训练投影后，与文字上下文、几何特征一起用于候选评分。
- [x] 当前A2候选评分没有调用SigLIP2文字编码或直接比较同一SigLIP2空间中的图文相似度。
- [x] 原GraphNav的 `ObservedSigLIPMatchingEncoder.texts` 已提供冻结SigLIP2文字编码能力；这证明已有实现可供后续可行性检查，不证明加入A2一定有效。

调查结论：

- 现状是：图片和文字各自使用已有冻结模型，新网络学习它们如何共同决定排序；没有直接使用SigLIP2原生图文相似度作为A2排序输入。
- 关键约束是：本轮代码已固定，不能向正在训练或等待评估的模型静默添加特征；新增诊断也不得占用训练显卡或读取独立验证来选方案。
- 之前尚未明确、现在确认的是：已有冻结图文编码器提供可复用的文字接口，可以在后续版本中进行独立的训练内部可行性检查。当前BERT和SigLIP2向量也不能直接做余弦相似度，维度和表征空间不同。
- 基于以上，判断是：用冻结模型现成的图文对应能力减少小样本学习负担，是值得验证的方向，但当前证据不支持将其认定为性能不足的唯一原因或已有效方案。

补充澄清方向和距离：`model.LandmarkBeliefNetwork.forward` 明确把预测方向与候选方向的对齐、预测距离与候选距离的差加入评分特征，所以两者并非只通过共享参数间接影响候选排序。最终 `relation_v3_fusion.proposal_with_quality` 仍以候选已有位置构造位置分布，没有用这两个预测直接移动候选坐标。先前“没有直接修正位置”的结论保持成立。

本项未执行新性能实验，未使用Seen/Unseen；A2超过A0仍未得到证明。
